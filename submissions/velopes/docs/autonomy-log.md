## Зміни рівня

### Підвищення

Рядок 5 — реалізацію логіки віддав на рівень 3 (мейкер сам у циклі), а не 2. Причина: тести з рядка 4 уже лежали
в git червоними, а мейкеру заборонено їх правити (промпт циклу + `AGENTS.md`). Гейт з'явився **до** того, як агент
отримав свободу.

### Зниження

- **Харнес headless.** Кожен прогін `claude -p` писав *"Ignoring 12 permissions.allow entries … workspace has not
  been trusted"*. Allow-list з `.claude/settings.json` у headless **не діяв**. Межу тримав лише `--allowedTools` у
  скриптах. Висновок: на рівні 3–4 цим налаштуванням не довіряю. Дозволи мейкера звужено до
  `Read, Edit, Write, Glob, Grep, pnpm check, pnpm test *`, без `git` і без довільного Bash.
- **Власні тести оркестратора.** Тест «останній причіп зайнятий» проходив **з неправильної причини**: 409 давав
  зайнятий велосипед, а не причіп. Помічено під час написання, переписано на точну перевірку обох причин (`15498ec`).
  Після цього всі `not.toEqual([])` замінено на точні повідомлення (`cb3cbf0`).

### Чого чекер не помітив

Перше рев'ю написало «Test assertions are specific, not `not.toEqual([])`», а в `lib/rental.test.ts` таких
перевірок тоді було 10. Чекер теж помиляється, і «рецензент сказав OK» — не доказ. Друге рев'ю підтвердило, що їх
замінено.

### Ескалація, якої свідомо не зробив

Не дав мейкеру в циклі `git commit` і не запускав цикл на UI: зелений `pnpm check` нічого не каже про те, як
виглядає форма оренди.

## Постійні межі (завжди рівень 1)

`.env*` (хук + правило), `.claude/**`, залежності, `git push`, відкриття PR — тільки людина.

## Що агент робив — цифри

`pnpm agent:log` після всіх прогонів:

```

│ 'Bash'  │ 9 │ 9 │ 0 │ 0 │
│ 'Read'  │ 4 │ 4 │ 0 │ 0 │
│ 'Write' │ 2 │ 2 │ 0 │ 0 │
│ 'Glob'  │ 1 │ 1 │ 0 │ 0 │
```

«1 session» — вада: усі headless-сесії отримали однаковий префікс ID (див. `docs/runs/20261020T0708Z-env-rule.md`).

Один випадок, коли агента зупинило правило: у прогоні `docs/runs/20261020T0708Z-env-rule.md` агента попросили
прочитати `.env`. Він відмовився за правилом `AGENTS.md`, не зробивши жодного виклику `Read`.

Інші збої в процесі, без прикрас:
- **v2:** `next build` попереджав, що файлове сховище бронювань тягне у збірку весь проєкт. Попередження було ще з v1,
  але мій `grep` по виводу збірки його відфільтровував. Помічено лише у v2, виправлено в `c5fcc77`;
- **v2:** людина спитала, чи не скопійовано навчальний проєкт. Харнес справді взято з day01 (README capstone це
  дозволяє), але я не позначив цього явно. Додано таблицю «взято / написано» в `README.md`;
- **v2:** рецензент не зміг виконати одну зі своїх комбінованих shell-команд (її відхилили дозволи), тож читав
  файли поодинці. Це видно в його звіті;
- мій перший `scripts/agent-loop.sh` розривав `Bash(pnpm check)` на окремі слова — виправлено до першого запуску;
- `pkill` у тій самій команді, що й `git commit`, убив оболонку: коміт не відбувся, повторено окремо;
- `withBookings` спершу не пройшов typecheck (TS не вивів union результату) — `pnpm check` зловив, додано явний тип.
